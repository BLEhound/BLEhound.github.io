# BLEhound Analyzer（上位机）

**BLEhound Analyzer** 是 BLEhound dongle 的桌面上位机：以 Wireshark 4.6 为基础、围绕这款
嗅探器重新构建。它自己直接和板子通信——不需要 Python，也不需要 `extcap` 插件——并且补上了
一个 BLE 嗅探器该有的面板：实时设备列表、带信道热力图的连接视图、请求/响应事务、上位机解密
和固件升级。Wireshark 对 BLE 抓包能做的一切，它照样能做。

安装包：Windows 10/11 用 `BLEhound-Analyzer-<版本>-x64.exe`（可与原版 Wireshark 并存，
不需要 Npcap），macOS 用 `BLEhound Analyzer.app`。界面语言跟随系统（English / 中文）。

![插着三块板子时的欢迎页](img/analyzer/01-welcome.png)

## 第一次启动

插上 dongle 后启动程序。每块板子都会成为一个独立的抓包接口——
**BLEhound Sniffer CH37 / CH38 / CH39: COMx**；插了两块以上时，还会多出一个
**3ch aggregated（三信道聚合）** 接口，把几块板子合并成一路数据流。默认选中的就是聚合接口，
直接点 **开始** 即可。

欢迎页右侧的侧栏会轮播一些小提示（显示过滤器、硬件说明），并链接到本文档站。

## 面板的显示与隐藏

![视图菜单](img/analyzer/13-view-menu.png)

**BLEhound 设备**、**看到的设备**、**事务**、**连接** 四个面板都是可停靠面板。
在 **视图** 菜单里勾选或取消即可显示或隐藏，它们和 Wireshark 自己的分组列表、分组详情、
分组字节流并列；也可以点面板标题栏上的 × 关闭，或用 ⧉ 按钮把面板浮出主窗口。
你的选择会在下次启动时保留。

## BLEhound 设备面板

![设备面板](img/analyzer/02-device-panel.png)

右上角的面板列出已连接的板子：各自守护的信道、串口、状态（空闲时为*扫描中*、*抓包中*、
*空闲*）、SYNC 同步线状态、固件版本和本次会话的包数。板子的身份从它发出的第一帧学到；
在那之前按串口顺序排列。

下方是**采集设置**（下次开始抓包时生效）：

- **单板** —— 在 37 / 38 / 39 之间轮流扫描，或固定在某一个广播信道。
- **目标设备** —— 只跟随这个地址。在 *看到的设备* 面板里一键填入。
- **包含 CRC 校验错误的包** —— 保留校验失败的包，排查信号弱的问题时有用。
- **单目标模式** —— dongle 一次只跟随一个连接。
- **经上位机的多板联合跟随** —— 聚合抓包的后备方案；正常情况下板子抓到 `CONNECT_IND`
  后会通过板间链路自己交给其他板子。

**升级固件…** 打开[固件升级](#firmware-update)对话框。

## 看到的设备

![看到的设备](img/analyzer/03-devices-seen.png)

没有抓包任务时 dongle 也一直在监听，所以板子一插上这个列表就是活的。每一行是一个设备：
名称、地址、地址类型（公共、静态随机、可解析随机、不可解析随机）、PHY、厂商、最近出现时间；
长时间没再出现的设备会被自动移出。搜索框可按名称、地址或厂商过滤；双击名称可以给设备起自己的
名字。

选中一个设备点 **跟随选中的设备**，它就成为所有板子的抓包目标。如果设备使用轮换的可解析随机
地址且 IRK 已知（见 *密钥*），列表会**按身份合并为一行**，嗅探器在它换地址后也能继续跟随。
**只显示目标相关的包** 会给包列表加上对应的显示过滤器。

## 设备密钥

![设备密钥对话框](img/analyzer/04-keys-dialog.png)

**密钥…** 打开密钥库。每个设备可以填身份地址、**IRK** 和 **LTK**：

- **跟随使用可解析随机地址（RPA）的设备需要 IRK。** 这类设备每隔几分钟就换一次地址；
  没有 IRK，目标过滤只认一个地址，设备一换地址就跟丢。有了 IRK，嗅探器能把每个新地址解析回
  身份地址，*看到的设备* 里按身份只显示一行，换地址后跟随照样继续。
- **解密被跟随的连接需要 LTK。** 抓包时上位机用 LTK 解密链路，把明文写进抓包文件，并把
  解密出来的控制 PDU（信道图、连接参数、PHY 更新）回传给 dongle，这样它才能在加密连接经历
  这些更新时继续跟随。

**新设备一般要跟两次。** 第一次跟随时通常还没有 LTK：链路一加密，dongle 读不到加密的控制
PDU，到下一次信道图或参数更新时多半就跟丢了。从通信双方之一拿到 LTK（配对日志，或用
[安全工具](https://github.com/BLEhound/BLEhound/tree/main/host/security) 恢复 Legacy 配对
的密钥），填到这里，再跟一次：从第二次抓包起整条连接就能全程解密、一直跟到结束。

密钥按十六进制、LSO 在前的顺序填写，和设备自己日志里打印的一致；也可以把包含
`IRK wire/LSO-first : …` 这类行的控制台输出整段粘贴进来，点 **从日志导入**。
LE Secure Connections 的密钥必须从通信双方之一取得，无法被动破解。

## 抓包

![抓包中：连接面板与事务面板](img/analyzer/07-capturing.png)

包列表就是 Wireshark 的，加了两处：一列 **Payload（载荷）**，以及 **Time** 列表头上的
时间格式菜单。状态栏显示当前正在抓的接口。

三块板子的聚合抓包同时守住三个广播信道，通过 SYNC 线对齐各板时间，把多块板同时听到的包去重，
并让所有板子并行跟随连接。单块板也可以从它自己的接口单独抓。

### 层级工具栏

![层级工具栏](img/analyzer/11-layer-toolbar.png)

一键套用某个协议层的显示过滤器：**全部**、**包**、**链路层**、**LLCP 包**、**LLCP 事务**、
**L2CAP 事务**、**SMP 事务**、**ATT 包**、**ATT 事务**。生成的过滤器会显示在过滤栏里，
可以继续在此基础上修改。

![ATT 事务过滤](img/analyzer/10-layer-att.png)

### 连接面板

![连接面板](img/analyzer/08-connection-panel.png)

按接入地址选择一个连接，即可看到它的中心与外设、间隔、潜伏期与监督超时、PHY、信道、
信道选择算法、是明文/已加密/正在解密，以及经历了多少次参数/信道图/PHY 更新。
**热力图** 显示 37 个数据信道：绿色格子有包（浅绿少、深绿多），红色格子 CRC 错误超过两成，
带阴影的格子不在当前信道图里。悬停某个格子可看具体数字。

### 事务面板

![事务面板](img/analyzer/09-transactions-panel.png)

把 LLCP、L2CAP、SMP、ATT 各层的请求/响应配对起来：两半各自的帧号、方向（中心 → 外设或反向）、
耗时、状态（*完成*、*等待响应*、*超时*、*配对失败*）和载荷。用 **层** 下拉框只看某一个
协议；双击一行可跳到对应的帧。

## 固件升级 { #firmware-update }

![固件升级对话框](img/analyzer/05-dfu-dialog.png)

设备面板里的 **升级固件…** 通过 USB 把签名的应用镜像（`blehound_ota.bin`）写进板子：
选镜像、勾选板子、点 **开始升级**。每块板会先切换进固件加载器，经 SMP 上传镜像，然后重启，
对话框会等待嗅探固件重新枚举——每块板大约五秒。升级前请先停止抓包。

## 捕获选项

![捕获选项](img/analyzer/06-capture-options.png)

捕获选项对话框只保留了对 BLE 嗅探器有意义的内容：接口、捕获长度与缓冲区、输出文件和
停止条件。混杂模式、BPF 捕获过滤器和远程接口都被隐藏。

## 关于

![关于对话框](img/analyzer/12-about.png)

**帮助 → About BLEhound Analyzer** 显示版本、编译信息和所用的库；帮助菜单里还有
*BLEhound 文档*、*快速上手* 和 *反馈问题* 的直达链接。

## 文件存放位置

- 设置与密钥：Windows 在 `%APPDATA%\BLEhound Analyzer`，macOS/Linux 在
  `~/.config/blehound-analyzer` —— 与 Wireshark 自己的配置分开。
- 抓包文件是普通的 pcapng（`LINKTYPE_BLUETOOTH_LE_LL_WITH_PHDR`），原版 Wireshark 同样能打开。
